# Установка, настройка и восстановление

[English](INSTALLATION.md) · [Архитектура](ARCHITECTURE.ru.md) · [Руководство](USER-GUIDE.ru.md)

## Текущий статус: готовой установки с нуля нет

Репозиторий содержит часть исходников, а не установщик и не полный бэкап. **Не заменяйте им рабочую установку.** Не восстановлены и не проверены развёрнутые файлы Docker Compose, команды `/usr/local/bin/pi-*`, systemd-служба, сертификаты, конфигурация, исходный `logo.png` и данные сервисов. В коде есть имена и пути первоначального устройства. Полная установка, обновление, откат и восстановление на новом Pi не проверены.

## 1. Подготовка устройства

- Raspberry Pi с Raspberry Pi OS или совместимым Debian, достаточным местом, охлаждением и административным доступом. Проверенной матрицы моделей и ОС пока нет.
- Доверенная локальная сеть и SSH. Для удалённого доступа заранее подключите устройство к своему Tailscale и сохраните резервный путь доступа до изменения сети.
- Выбирайте сервисы с учётом памяти и процессора: Pi 3 с 1 ГиБ нельзя считать эквивалентом Pi 5 с 8 ГиБ. Тяжёлые сервисы разумно запускать по необходимости.
- Docker, Python 3 и системные зависимости устанавливайте после проверки будущего установщика. В исходниках используются Paramiko и PyKeePass, а отдельные функции зависят от Docker, NetworkManager, Tailscale, cloudflared, rclone, CUPS и других компонентов. Это не полный проверенный список.

## 2. Проверка исходников без установки

```sh
git clone https://github.com/sm0k3net/pi-control.git
cd pi-control
python3 -m compileall -q src
node --check src/app.js
node --check src/filemanager.js
```

Для приватного репозитория нужна авторизация GitHub. Команды проверяют только синтаксис; запуск сервера после одного клонирования не воспроизводит рабочую систему.

## 3. Инвентаризация действующего Pi

Получив разрешённый доступ, составьте список установленной панели, systemd-служб, скриптов, образов и Compose, томов и сетевых настроек **без вывода секретов**. Сверьте контрольные суммы с репозиторием и версии. Сохраните независимый проверенный бэкап до изменений. Пароли, KDBX, токены, закрытые ключи, конфигурацию сетей, содержимое баз и бэкапы не добавляйте в Git.

## 4. Что нужно завершить для установки с нуля

1. Восстановить и проверить реальные скрипты, службы и обезличенную конфигурацию стека.
2. Вынести имена пользователя, домен, адреса, пути, названия контейнеров и порты в проверяемые настройки.
3. Создавать отдельные учётные данные и TLS-сертификат для каждого устройства; ограничить права файлов, Docker и команд.
4. Зафиксировать зависимости, добавить лицензии компонентов и безопасную повторную установку с миграциями.
5. Проверить чистую установку, обновление, откат и полное восстановление на тестовых устройствах; составить матрицу совместимости.
6. На основе проверенных файлов описать настройку, сеть, брандмауэр и восстановление.

До выполнения этих шагов команды «установить одной строкой» нет.

## Настройка уже работающей панели

1. Откройте фактический HTTPS-адрес в доверенной сети или Tailscale, проверьте отпечаток сертификата и войдите под отдельным паролем панели.
2. В **«Настройки»** проверьте интерфейсы и Wi-Fi. До переключения сети убедитесь, что есть резервный путь доступа.
3. В **«Сервисы»** включайте нужные приложения. Agent Zero, n8n, Nextcloud, ONLYOFFICE и остальные настраиваются в собственных интерфейсах и требуют отдельных учётных данных и постоянного хранения.
4. В **«Уведомления»** укажите токен Telegram-бота и ID чата, включите отправку и выполните тест. См. [оповещения](USER-GUIDE.ru.md#уведомления-telegram).
5. В **«Узлы Pi»** проверьте отпечаток SSH по доверенному каналу, укажите пароль вручную или через KDBX, проверьте ресурсы и настройте только принадлежащий вам или разрешённый узел. Затем проверьте сертификат и доступ к панели узла.
6. Настройте бэкап на отдельный носитель и выполните пробное восстановление в изолированном окружении. Для облака нужен отдельно настроенный rclone и отсутствующие в снимке системные скрипты.

Не публикуйте пароли, базы, KDBX, сертификаты, токены, персональные данные и бэкапы, в том числе в приватном Git-репозитории.
